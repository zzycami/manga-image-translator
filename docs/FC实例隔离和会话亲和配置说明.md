# FC实例隔离和会话亲和配置说明

## 实例隔离

### 是否需要？❌ **不需要开启**（保持关闭）

**实例隔离的作用：**
- 确保不同请求使用不同的函数实例
- 避免请求之间的相互影响
- 提高安全性（请求之间完全隔离）

**适用场景：**
- 需要严格隔离的场景
- 安全要求极高的场景
- 多租户场景

**我们的服务：**
- 每个翻译请求是独立的
- 请求之间不会相互影响
- 不需要严格隔离
- 无状态服务

**建议：** ❌ **不勾选**（保持关闭）

**原因：**
1. 我们的服务是无状态的
2. 请求之间不会相互影响
3. 开启可能增加资源消耗
4. 可能影响性能

## 会话亲和

### 是否需要？❌ **不需要开启**（保持关闭）

**会话亲和的作用：**
- 确保同一会话的请求路由到同一个实例
- 保持会话状态
- 适合有状态的场景

**适用场景：**
- 需要保持会话状态的场景
- WebSocket连接
- 需要维护状态的场景

**我们的服务：**
- 每个翻译请求是独立的
- 不需要保持会话状态
- 无状态服务
- 每个请求都是独立的HTTP请求

**建议：** ❌ **不勾选**（保持关闭）

**原因：**
1. 我们的服务是无状态的
2. 每个请求都是独立的
3. 不需要保持会话状态
4. 开启可能影响负载均衡

## 我们的服务特点

### 无状态服务

**特点：**
- 每个翻译请求是独立的
- 不需要保持会话状态
- 请求之间不会相互影响
- 可以任意路由到任何实例

**因此：**
- ❌ 不需要实例隔离
- ❌ 不需要会话亲和
