# FC部署说明 - 网页模式 vs API模式

## 当前部署情况

### ✅ 已部署：API服务（fc_server.py）

**部署内容：**
- 使用 `fc_server.py` 作为HTTP服务器
- 提供REST API接口
- 不包含Web UI界面

**可用接口：**
- `/health` - GET - 健康检查
- `/` - GET - 根路径
- `/translate` - POST - 翻译功能

**访问地址：**
```
https://manga-tanslator-pssdhxnbcm.cn-hangzhou.fcapp.run
```

### ❌ 未部署：网页模式（server/main.py）

**网页模式功能：**
- Web UI界面（前端页面）
- 可视化操作界面
- 文件上传、预览等功能
- 通常运行在 `server/main.py`

**当前状态：** 未部署，不可访问

## 两种模式的区别

### API模式（当前部署）

**特点：**
- ✅ 只提供API接口
- ✅ 适合程序调用（Kotlin后端）
- ✅ 轻量级，资源占用少
- ❌ 没有Web UI界面
- ❌ 不能通过浏览器直接操作

**使用场景：**
- 后端服务调用
- 程序集成
- 自动化处理

### 网页模式（未部署）

**特点：**
- ✅ 提供Web UI界面
- ✅ 可以通过浏览器直接操作
- ✅ 可视化操作
- ❌ 需要更多资源
- ❌ 不适合程序调用

**使用场景：**
- 手动操作
- 测试和演示
- 个人使用

## 如果需要网页模式

### 方案1：本地运行网页模式

在本地运行 `server/main.py`：

```bash
cd /Users/zhouzeyong/Documents/GitHub/manga-image-translator
python server/main.py --use-gpu --host=0.0.0.0 --port=8000
```

然后访问：`http://localhost:8000`

### 方案2：在FC中部署网页模式

如果需要将网页模式也部署到FC：

1. **修改Dockerfile**，包含Web UI
2. **修改启动命令**，运行 `server/main.py`
3. **重新构建和推送镜像**
4. **创建新的函数**（或修改现有函数）

**注意：** 这需要额外的配置和资源。

### 方案3：部署两个服务

- **API服务**（当前）：用于程序调用
- **Web UI服务**（新）：用于网页访问

## 当前架构

```
Kotlin后端
    ↓
FC函数（API服务）
    ↓
翻译功能
```

**网页模式不在这个架构中。**

## 总结

### 当前状态

- ✅ **API服务已部署**：可以通过API调用翻译功能
- ❌ **网页模式未部署**：不能通过浏览器访问Web UI

### 如果需要网页模式

1. **本地运行**：在本地运行 `server/main.py`
2. **部署到FC**：需要额外配置和部署
3. **部署两个服务**：API服务 + Web UI服务

## 推荐

**当前架构（API模式）适合：**
- ✅ 后端服务调用
- ✅ 程序集成
- ✅ 生产环境

**如果需要测试或手动操作：**
- 可以在本地运行网页模式
- 或使用API接口进行测试
