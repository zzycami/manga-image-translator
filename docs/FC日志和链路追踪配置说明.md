# FC日志和链路追踪配置说明

## 日志功能

### 是否需要？✅ **强烈建议开启**

**日志的作用：**
- 查看函数执行日志
- 查看错误信息和异常堆栈
- 查看函数输出（print、logger等）
- 调试和排查问题
- 监控函数运行状态

**我们的服务：**
- 翻译过程可能出错，需要查看日志排查
- 需要查看API调用情况
- 需要查看模型加载情况
- 需要查看错误信息

**建议：** ✅ **勾选开启**

### 日志配置

**开启日志后，可以：**
- 在FC控制台查看日志
- 在日志服务（SLS）中查看详细日志
- 设置日志保留时间（建议7天）
- 查看实时日志流

## 链路追踪

### 是否需要？⚠️ **可选**（建议开启）

**链路追踪的作用：**
- 分析函数性能
- 查看函数调用链路
- 分析耗时分布
- 排查性能问题

**我们的服务：**
- 翻译任务可能耗时较长
- 需要分析各个步骤的耗时
- 需要优化性能

**建议：** ✅ **建议开启**（有助于性能分析）

### 链路追踪配置

**开启链路追踪后，可以：**
- 查看函数执行时间分布
- 分析性能瓶颈
- 优化函数性能

## 推荐配置

### 方案1：最小配置（初期测试）

| 配置项 | 状态 | 说明 |
|--------|------|------|
| **日志** | ✅ **勾选开启** | 必须开启，用于调试 |
| **链路追踪** | ❌ 不勾选 | 可选，初期可以不开启 |

### 方案2：完整配置（推荐）

| 配置项 | 状态 | 说明 |
|--------|------|------|
| **日志** | ✅ **勾选开启** | 必须开启，用于调试 |
| **链路追踪** | ✅ **勾选开启** | 建议开启，用于性能分析 |

## 详细说明

### 日志功能（强烈建议开启）

**为什么必须开启：**
1. ✅ 翻译过程可能出错，需要查看日志排查
2. ✅ 需要查看API调用情况
3. ✅ 需要查看模型加载情况
4. ✅ 需要查看错误信息和异常堆栈
5. ✅ 调试和排查问题

**开启后可以：**
- 在FC控制台查看实时日志
- 在日志服务（SLS）中查看详细日志
- 设置日志保留时间
- 搜索和过滤日志

**成本：**
- 日志服务有免费额度
- 超出部分按量付费
- 通常成本很低

### 链路追踪（建议开启）

**为什么建议开启：**
1. ✅ 翻译任务可能耗时较长，需要分析性能
2. ✅ 可以查看各个步骤的耗时
3. ✅ 可以优化函数性能
4. ✅ 可以排查性能问题

**开启后可以：**
- 查看函数执行时间分布
- 分析性能瓶颈
- 优化函数性能

**成本：**
- 链路追踪有免费额度
- 超出部分按量付费
- 通常成本很低

## 最终建议

### ✅ 日志功能：**勾选开启**（必须）

**原因：**
- 必须用于调试和排查问题
- 成本很低
- 对开发调试非常重要

### ✅ 链路追踪：**建议勾选开启**（推荐）

**原因：**
- 有助于性能分析
- 成本很低
- 对优化性能有帮助

## 配置总结

| 配置项 | 推荐状态 | 优先级 |
|--------|---------|--------|
| **日志** | ✅ **开启** | 高（必须） |
| **链路追踪** | ✅ **开启** | 中（推荐） |

## 注意事项

1. **日志保留时间**：建议设置为7天（默认值）
2. **日志级别**：可以在代码中设置日志级别
3. **成本**：日志和链路追踪都有免费额度，通常成本很低
4. **性能影响**：开启日志和链路追踪对性能影响很小

**推荐配置：**
- ✅ **日志功能**：勾选开启（必须）
- ✅ **链路追踪**：勾选开启（推荐）

**原因：**
- 日志是调试和排查问题的必需品
- 链路追踪有助于性能分析
- 成本很低，收益很大
