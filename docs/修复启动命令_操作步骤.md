# 修复启动命令 - 操作步骤

## 问题原因

官方镜像的ENTRYPOINT是 `["python", "-m", "manga_translator"]`，FC的启动命令会作为参数传递，导致执行了错误的命令。

## 解决方案

### 方案1：在FC中填写启动命令（快速修复）

#### 步骤1：修改函数配置

1. 在FC函数详情页面
2. 点击 **"配置"**（Configuration）标签
3. 找到 **"启动命令"**（Startup Command）配置
4. 填写完整的启动命令：

```
gunicorn fc_server:app -k uvicorn.workers.UvicornWorker -b 0.0.0.0:9000 --timeout 600
```

**重要：** 必须填写完整的命令，覆盖镜像的默认ENTRYPOINT

#### 步骤2：保存配置

1. 点击 **"保存"** 或 **"更新"**
2. 等待配置生效（可能需要几分钟）

#### 步骤3：重新测试

1. 点击 **"测试"** 标签
2. 重新测试函数

### 方案2：修改Dockerfile并重新构建（彻底解决）

如果方案1不行，需要修改Dockerfile并重新构建镜像。

#### 步骤1：修改Dockerfile

我已经修改了 `Dockerfile.fc.optimized`，添加了 `ENTRYPOINT []` 来覆盖官方镜像的ENTRYPOINT。

#### 步骤2：重新构建镜像

```bash
cd /Users/zhouzeyong/Documents/GitHub/manga-image-translator

# 设置代理
export https_proxy=http://127.0.0.1:7890
export http_proxy=http://127.0.0.1:7890
export all_proxy=socks5://127.0.0.1:7890

# 重新构建镜像
docker build --platform linux/amd64 -f Dockerfile.fc.optimized -t manga-image-translator:fc-optimized .
```

#### 步骤3：标记并推送镜像

```bash
# 标记镜像
docker tag manga-image-translator:fc-optimized \
  manga-translator-registry.cn-hangzhou.cr.aliyuncs.com/manga-translator/manga-image-translator:fc-v2

# 推送镜像（使用新Tag）
docker push manga-translator-registry.cn-hangzhou.cr.aliyuncs.com/manga-translator/manga-image-translator:fc-v2
```

#### 步骤4：在FC中更新镜像

1. 在FC函数配置中
2. 修改镜像地址，使用新Tag：`fc-v2`
3. 保存配置
4. 重新测试

## 启动命令说明

**正确的启动命令：**
```
gunicorn fc_server:app -k uvicorn.workers.UvicornWorker -b 0.0.0.0:9000 --timeout 600
```

**参数说明：**
- `gunicorn`：WSGI HTTP服务器
- `fc_server:app`：FastAPI应用
- `-k uvicorn.workers.UvicornWorker`：使用Uvicorn worker
- `-b 0.0.0.0:9000`：绑定到9000端口
- `--timeout 600`：超时时间600秒
